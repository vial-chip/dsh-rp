# @deepseek-ai/dsh-roleplay

[English](README.md) | 中文

## 概述

在角色扮演会话中持续保存一个角色的身份与已记录状态。角色卡在首次互动时固定，因此后续 skill 文件编辑只影响新会话。人工状态编辑立即保存，仅在模型主动读取时进入上下文。撤销与重生成撤回最近已完成的互动，恢复其状态修改并保留人工编辑。

<a id="use-this-package"></a>
## 使用本包

Web 组合挂载此服务并提供 `roleplay` 预设。自定义组合将其与 agent 注册表、会话、会话投影、session-query、skill 和系统提示词服务共同挂载。Session-query 为撤回提供完整互动历史，包括常驻尾部以外的事件。

### 配置

| 字段 | 默认值 | 含义 |
|---|---|---|
| `maxFields` | `64` | 每类状态最多保存的字段数 |
| `maxFieldLength` | `80` | 每个字段名的最大字符数 |
| `maxTextLength` | `2000` | 每个文字值的最大字符数 |

限制必须为正安全整数。生成的[配置目录](../../../docs/config-catalog.zh.md#deepseek-aidsh-roleplay)拥有完整配置参考。

### 角色卡与状态

内置角色卡为 `daily-companion`。名称以 `roleplay-` 开头的可用 skill 提供其他角色卡。角色卡固定前允许选择；不可用的卡会明确报错。每个会话保存自己的固定角色卡及四类状态。世界、身体和服饰值为文字，关系值为有限数值。模型更新对关系应用增减量，人工编辑直接设定值。

`previewCard` 读取当前选择的完整角色卡供发送前预览，不固定角色卡，也不追加事件；固定后返回已保存副本。

面板读取和人工编辑不发送消息、不触发推理，也不改变提示词。模型只有调用对应读取工具时才会收到编辑后的状态。叙事文字不更新已记录状态。

### 撤销与重生成

这两项操作要求角色扮演会话处于空闲且仍打开，并有最近一轮已完成互动。撤销将用户输入的文字恢复到输入框；没有用户输入的互动返回 `null`。重生成以新消息标识重新发送原始触发消息的内容与来源，并移除已消费的浏览器请求标识，保留非人工来源，因此随后撤销仍不回填文字。没有任何原始消息的空互动会在撤回前拒绝重生成。两项操作均撤回该互动的有效历史，恢复其模型工具修改的字段，保留自该互动开始以来记录的人工替换值。其他副作用不在回退范围内。撤回在下次请求能够开始前保存，若中途被打断则在重新打开时完成。

<a id="model-experience"></a>
## 模型体验

### 角色指令

#### 模型看到什么

角色扮演提示词以这些指令替换其他已组装的段落与上下文，随后附上 `角色卡：` 及固定的角色卡内容。动态状态通过工具结果进入上下文。后续有效历史不包含已撤回的互动消息。

##### 稳定的角色扮演指令

```markdown
你正在与用户进行单人沉浸式角色扮演。你扮演角色卡指定的主要角色，与用户自然地共同生活和互动。
始终遵循角色的身份、背景、性格和表达方式，以自然台词、简短动作和必要的环境描写回应。可以描写临时路人，避免抢走主要角色的互动。
用户独自掌握自己的台词、行动、决定和内心体验。不要替用户说话、决定、行动，也不要断言用户的感受或想法。
故事只随用户输入或明确的继续操作推进。回应当前互动，给用户留下选择和接话的空间，不自行跳过重要时刻。
使用中文表达，保持角色连贯、细节适量，避免重复角色设定、长篇总结和脱离角色的说明。
```

#### Token 影响

指令与角色卡内容为每次请求贡献固定输入。人工编辑不增加模型输入。状态读写工具拥有各自的结果成本。

#### KV Cache 影响

普通状态修改保持指令与角色卡前缀不变。撤回改变有效历史。供应商缓存命中取决于供应商及请求顺序。

<a id="known-limitations-and-deferred-work"></a>
## 已知限制与延期工作

已记录状态独立于叙事和模型记忆。

- 在模型选择读取前，人工编辑可能与模型当前认知不同。
- 撤回只恢复本会话的角色扮演状态；无关工具副作用仍然保留。
- 撤销只恢复文字到输入框；重生成保留原消息内容，包括非文字部分。
