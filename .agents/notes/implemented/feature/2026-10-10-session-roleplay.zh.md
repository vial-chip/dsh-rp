# Agent Note: 单会话角色扮演

Status: implemented

[English](2026-10-10-session-roleplay.md) | 中文

## 问题

角色扮演需要稳定的角色、可查看的故事状态，以及用户对自身行动的控制。自动注入每次状态修改会增加模型输入，即使当前对话不需要该状态，也会改变请求前缀。

## 决策

原生角色扮演预设拥有单会话的固定角色卡与已记录状态。角色定义由 skill 提供，内容在首次互动时固定，因此重新打开后保持相同身份，后续文件修改仍可供新会话使用。不维护跨会话关系记忆或共享角色档案。

世界、身体、服饰和关系各有独立的读取与更新工具。人工编辑立即保存，但只有模型自愿调用对应读取工具时才进入上下文。叙事文本不写入已记录状态。固定指令、角色卡和未改变的工具定义保留请求前缀复用潜力，不承诺提供商实际命中缓存。

撤销与重生成从有效历史撤回一轮已完成互动，并恢复其中由模型写入的字段，保留后续人工替换值。审计事件仍持久保存。在下一次请求开始前，历史移除与恢复状态均已保存，重新打开会话会完成被打断的撤回。回退只覆盖会话角色扮演状态，不逆转无关工具的副作用。

当前操作细节由[角色扮演服务](../../../../packages/roleplay/roleplay/README.zh.md)、[状态工具](../../../../packages/roleplay/tool-roleplay/README.zh.md)和[原生客户端](../../../../packages/client/ui-roleplay/README.zh.md)说明。[子系统参考](../../../../docs/subsystems/roleplay.zh.md)拥有保存的类型。

## 考虑过的替代方案

**聚合状态工具。** 独立能力支持分别开关，并将每次结果限制在请求的主题内。

**动态系统指令。** 每次状态改变都修改系统提示词，会把人工面板编辑与模型输入耦合，并改变稳定前缀；自愿读取让这项成本显式发生。

**专用会话入口。** 原生新建入口、输入框和侧边栏书签保留已有会话交互，并支持按需查看各类状态。

## 结果与取舍

已记录面板可能与叙事或模型保留的理解不同。人工编辑后，模型可能继续保留旧值，直到自行选择对应读取工具。这是保持工具调用可选、普通对话无需强制读取状态的代价。

无密钥循环、JSONL 刷新与重开、SDK 回放和真实浏览器测试覆盖状态撤回与原生控件。稳定前缀观察不测量提供商缓存命中、token 计费或延迟；这些需要带凭据的提供商运行。
